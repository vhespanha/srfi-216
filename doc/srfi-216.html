(srfi 216): SICP Prerequisites (Portable)

A portable R7RS implementation of SRFI 216, written by Vladimir Nikishkin. It provides the primitives that Structure and Interpretation of Computer Programs assumes, so the book's code runs unchanged after (import (srfi 216)).

Dependencies: (scheme base), (scheme lazy), (scheme time), (srfi 18) and (srfi 27). Intended for teaching, not for production concurrency or randomness.

Exports

Constants

true
#t.
false
#f.
nil
The empty list, '().
the-empty-stream
The empty list, '(). It can never be the result of cons-stream.

Streams

(cons-stream a b) (syntax)
Expands to (cons a (delay b)): b is not evaluated until the cdr is forced. The cdr is an R7RS promise, so the book's own stream-car (car) and stream-cdr ((force (cdr s))) work as written.
(stream-null? obj)
Same as null?.

stream-car, stream-cdr and other stream helpers are deliberately not exported, so defining them yourself, as the book asks, does not clash with the import.

Time and randomness

(runtime)
The number of microseconds since the Epoch, as an exact integer, computed from current-second. Subtract two readings to time a computation. (The SRFI's own example prints a non-integer; this library follows the SRFI's text, which says an integer.)
(random x)
  • An exact positive integer x gives an exact integer in [0, x), via SRFI 27 random-integer.
  • Any other positive real x (inexact, or an exact non-integer such as 1/2) gives an inexact real in [0, x), computed as x times random-real.
  • Zero, a negative number, or a non-real signals an error.
The SRFI 27 default random source is randomized when the library loads, then mixed with the microsecond part of the current time, so each session sees a different sequence even on implementations whose randomization clock only ticks once a second.

Concurrency

(parallel-execute thunk ...)
Starts one SRFI 18 thread per thunk, waits for all of them to finish, and returns an unspecified value.
(test-and-set! cell)
cell is a pair, as in the book's (list false). If its car is false it is set to #t; either way the old value is returned. A single library-wide SRFI 18 mutex makes each call atomic with respect to every other call, so the book's make-mutex and serializers really exclude each other.
